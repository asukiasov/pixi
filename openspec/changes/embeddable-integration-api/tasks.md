  A code review (dispatched after the first commit, scoped to this task's diff) found one real Important-level bug, independently corroborated by a separate broader-scope review pass: `destroy()` only removes `container` from the DOM - it doesn't reset `js/workspace.js`'s module-level `state`/`root`, so the document-level Ctrl/Cmd+Z/Y shortcuts keep running against the destroyed instance's (now-detached) `layerStack`/`undoStack`, and `performUndo()`/`performRedo()` still call `autoSave()` → the closed-over `onChange` callback → `events.emit('change')`, invoking a host's registered handler on an instance it already destroyed.
